# 网络估算分 v0.1

这是供真实使用体验校准的展示版，并非完整 AIM 场景评级，也不是同路径实测评分。

## 数据与规则

- 每个地址族使用首页当前配置中的第一条对应 V4/V6 探针线路。切换线路后估算分跟随改变，不挑选得分最高的运营商。
- 采用当前探针延迟和窗口探测失败比例，结合 deb 最近同一测速批次的下载、上传 Mbps。TCP 重传次数不折算成丢包。
- 复用 Cloudflare AIM 的延迟、丢包、速度分段阈值；带宽项按下载 70% / 上传 30% 适配。
- `估算分 = round(clamp(延迟点数 + 失败率点数 + 带宽点数, 0, 60) / 60 × 100)`。
- 延迟分界 10/20/50/100/500 ms，点数 20/10/5/0/-10/-20；失败率分界 1%/5%/25%/50%，点数 10/5/0/-10/-20；速度分界 1/10/50/100 Mbps，点数 0/5/10/20/30。等值进入右区间。
- 尚未计入抖动、负载延迟或日间与晚高峰长期稳定性；分数用于节点概况参考，不代表游戏或视频的官方 AIM 等级。

## 缺项与异常

无测速、测速不完整、执行失败、探针请求失败、离线和无有效指标均不生成分数。完整测速记录的 `no_response` 对应方向以 0 Mbps 计入。始终使用最新批次，不用较早的成功掩盖最新失败。

测速超过 24 小时标较旧，超过 72 小时不计分。首页每分钟刷新测速数据，分数随现有探针更新；顶部原有 V4/V6 标签显示估算分；点击标签可看指标、测试时间、实际点数与说明。底部不新增评分行。
